# Аналитика онлайн-кинотеатра

Из папки с `docker-compose.yml`:

```sh
docker compose up -d --build
docker compose run --rm test
```

Топик, версия Protobuf-схемы, таблицы, панели Grafana и бакет создаются автоматически. Интеграционный тест отправляет событие с новым UUID через HTTP и сверяет все восемь полей в ClickHouse.

| Что открыть | Адрес | Доступ |
|---|---|---|
| Отправка события | http://localhost:8000/docs | `POST /events` |
| Пересчёт и экспорт за выбранную дату | http://localhost:8001/docs | `POST /recalculate/{day}`, затем `POST /export/{day}` |
| Дашборд | http://localhost:3000/d/cinema | `admin` / `cinema` |
| Файлы MinIO | http://localhost:9001 | `cinema` / `cinema-secret` |

**Продюсер.** JSON проверяется и кодируется по `movie.proto`. Топик `movie-events` имеет три партиции. Ключ `user_id` сохраняет порядок публикации событий пользователя. На трёх брокерах KRaft размещены две реплики каждой партиции. Настроены `acks=all`, `min.insync.replicas=1`, идемпотентный продюсер и повторы с растущей задержкой. Schema Registry хранит версии схемы. ID и версия идут в заголовках Kafka, тело содержит одно Protobuf-сообщение. ClickHouse читает тот же файл схемы через Kafka Engine и материализованное представление. Таблица событий разделена по месяцам и отсортирована по дню, пользователю и ID события.

**Данные для демонстрации.** При запуске генератор воспроизводит сеансы за последние девять дней, затем продолжает публиковать новые. У событий истории стабильные ID, а запросы к `events FINAL` исключают повторы. Для отключения генератора задай `GENERATE_EVENTS=0`. Первый дашборд заполняется после публикации событий и ближайшего пересчёта.

**Агрегация.** Сервис пересчитывает дневные метрики раз в `AGG_INTERVAL_SECONDS` секунд (по умолчанию 60). Даты указаны в UTC. Топ-10 считается по началам просмотра, среднее время — по завершениям, конверсия — отношение числа завершений к числу начал за день. Для retention когорта определяется первым `VIEW_STARTED`, возвратом считается любое событие в соответствующий день. Например, D7 за 8 марта показывает долю вернувшихся 8 марта среди тех, кто впервые начал просмотр 1 марта. На тепловой карте эта доля находится в строке «1 марта», столбце Day 7. Пустая ячейка означает отсутствие данных.

**Хранение и экспорт.** Готовые метрики хранятся в ClickHouse (`daily FINAL`) и PostgreSQL (`metrics`). Повторный расчёт заменяет весь набор значений за дату одной транзакцией в PostgreSQL. Grafana читает агрегаты ClickHouse. Метрики завершившегося дня экспортируются из PostgreSQL в `s3://movie-analytics/daily/YYYY-MM-DD/aggregates.csv`. Экспорт за ту же дату перезаписывает файл. При ошибке задача остаётся в PostgreSQL до следующего цикла.

Остановить проект с сохранением данных: `docker compose down`.
